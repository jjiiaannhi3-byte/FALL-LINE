# 滑雪姿态检测原型：接线与使用说明

本套程序采用胸口 ESP32-S3 + MPU6500、四肢各一个 ESP32-C3 + MPU6050，使用 ESP-NOW 通信。胸口的 DRV8833 驱动一个额定 3.3V 的普通两线直流偏心振动马达。

这是可用于接线、烧录和联调的原型程序。默认实现四肢角度采集、胸口角度采集、串口数据显示、静止校准、通信超时停振，以及胸口倾斜阈值提醒。四肢阈值提醒可以通过一个开关启用。角度阈值是演示参数，尚未经过滑雪教学验证。

## 1. 文件

```text
SkiMotion/
├─ 接线与使用说明.md
├─ SkiMaster/
│  ├─ SkiMaster.ino       胸口 ESP32-S3 主控
│  └─ MotionCommon.h     传感器与通信公共代码
└─ SkiNode/
   ├─ SkiNode.ino         四个 ESP32-C3 分控共用，逐个修改 NODE_ID
   └─ MotionCommon.h     与主控目录中的同名文件保持一致
```

引脚表使用 **GPIO 编号**，不是排针的物理序号。以下针对引出这些 GPIO 的通用开发板；具体板型未提供，接线前检查板上 GPIO 标注和原理图。已有屏幕、存储器等占用同一 GPIO 时，必须在程序中更换引脚。

## 2. 总体连接图

```text
左臂 C3 + MPU6050（ID 1） ──无线──┐
右臂 C3 + MPU6050（ID 2） ──无线──┤
左腿 C3 + MPU6050（ID 3） ──无线──┼─ 胸口 S3 + MPU6500
右腿 C3 + MPU6050（ID 4） ──无线──┘          │
                                            └─ DRV8833 ─ 振动马达
```

各无线节点需要自己的电池和稳压供电。无线节点之间不需要连接地线；同一节点内部必须共地。

## 3. 主控：ESP32-S3 与 MPU6500

| ESP32-S3 | MPU6500 模块 | 说明 |
|---|---|---|
| 3V3 | VCC / VDD | 使用支持 3.3V 供电的模块 |
| GND | GND | 共地 |
| GPIO8 | SDA / SDI | I²C 数据 |
| GPIO9 | SCL / SCLK | I²C 时钟 |
| GND | AD0 / SDO | 地址选择，地址为 0x68 |
| 3V3 | CS / nCS | 拉高选择 I²C 模式；已固定为 I²C 的模块按其说明接线 |
| 不接 | INT | 当前程序采用轮询 |

```text
ESP32-S3                     MPU6500
  3V3 ────────────────────── VCC
   │  └───────────────────── CS（若引出）
  GND ────────────────────── GND
   │  └───────────────────── AD0
  IO8 ────────────────────── SDA
  IO9 ────────────────────── SCL
```

若模块没有板载 I²C 上拉，在 SDA、SCL 上分别增加约 4.7kΩ 电阻上拉到 3.3V。已有上拉时不要无条件重复添加。程序检查 MPU6500 的 WHO_AM_I = 0x70，不把 MPU6050/MPU9250 当作 MPU6500 使用。

## 4. 主控：DRV8833 与振动马达

| ESP32-S3 / 电源 | DRV8833 | 说明 |
|---|---|---|
| 稳压后的 3.3V 马达电源 | VM / VIN | 不是电池原始正极 |
| GND | GND | 与 S3、电源共地 |
| GPIO4 | AIN1 / IN1 | 20kHz PWM |
| GPIO5 | AIN2 / IN2 | 当前程序保持低电平 |
| GPIO6 | nSLEEP / SLP | 高电平工作，低电平关闭 |
| 马达一根线 | AOUT1 / OUT1 | 马达接在两个输出之间 |
| 马达另一根线 | AOUT2 / OUT2 | 不直接接 GND |
| GND | BIN1、BIN2 | 未用的 B 通道输入固定为低 |
| 不接 | BOUT1、BOUT2 | 未用输出 |
| 不接 | nFAULT | 本版未读取故障脚 |

```text
稳压 3.3V ─────────────── VM
                         │
                 100nF + 100~470µF
                         │
公共 GND ─────────────── GND

S3 IO4 ──────────────── AIN1      AOUT1 ──┐
S3 IO5 ──────────────── AIN2              ├─ 3.3V 两线马达
S3 IO6 ──────────────── nSLEEP    AOUT2 ──┘
                         │
                       10kΩ
                         │
                        GND
```

nSLEEP 外接 10kΩ 下拉，确保主控复位时关闭马达。若模块自带 nSLEEP 上拉，需要检查分压后是否仍满足可靠低电平，必要时移除模块上拉。若模块把 nSLEEP 直接接电源，不可把 GPIO6 直接接到该电源；需要选用可独立控制 nSLEEP 的模块或修改模块连接。

表格按常见 **DRV8833 成品模块** 编写。裸芯片还需要按数据手册处理 AISEN/BISEN、电流设定及旁路电容，不应照此省略外围电路。马达启动/堵转电流必须在模块和电源允许范围内。LRA 线性振动马达不适用这套驱动方法。

## 5. 分控：ESP32-C3 与 MPU6050

四个节点接线相同，只修改节点 ID。

| ESP32-C3 | MPU6050 模块 |
|---|---|
| 3V3 | VCC（模块须支持 3.3V 输入） |
| GND | GND |
| GPIO4 | SDA |
| GPIO5 | SCL |
| GND | AD0 |
| 不接 | INT、XDA、XCL |

```text
ESP32-C3                     MPU6050
  3V3 ────────────────────── VCC
  GND ────────────────────── GND
   │  └───────────────────── AD0
  IO4 ────────────────────── SDA
  IO5 ────────────────────── SCL
```

AD0 接地时地址为 0x68；如果实际接高电平，需要把对应程序的 IMU_ADDRESS 改成 0x69。对于带稳压器的传感器模块，应核实 3.3V 输入后的芯片电压足够，且 I²C 上拉电压为 3.3V。

## 6. 电池与供电图

```text
单节锂电池：标称 3.7V，满电 4.2V
              │
       单节锂电池保护电路
              │
            电源开关
              │
       稳压 3.3V 升降压模块
              ├─ ESP32 的 3V3 + MPU 的 VCC
              └─ DRV8833 VM（仅主控）

所有模块负极接该节点的公共 GND
```

- 不要将锂电池直接接 ESP32 的 3V3，也不要用原始 4.2V 电池满功率驱动额定 3.3V 马达。
- 优先使用连续输出能力至少约 1A 的稳压方案作为初选，最终需按 ESP32 峰值电流、马达启动/堵转电流和模块降额核算；1A 不是无条件保证。
- 主控马达与传感器分支布线，驱动器附近放置去耦电容。马达与 IMU 机械隔离，避免振动污染测量。
- 电池保护电路不等于充电电路。另配匹配电芯的单节锂电池充电模块；边充边用需要带电源路径管理的方案。
- 不能默认所有开发板都允许“USB + 外部 3V3”同时供电。烧录时先断开外部稳压 3.3V，按开发板说明供电，避免反向灌电。
- 低温下续航会降低；按电芯温度规格充电，普通锂电池不要在零下直接充电。

## 7. Arduino IDE 烧录

1. 安装 Arduino IDE 2.x。
2. 开发板管理器中安装 **esp32 by Espressif Systems，版本 3.0.7**。本代码使用 3.x 的 ESP-NOW 接收回调及 LEDC 接口，不适用于未经修改的 2.x。
3. 如果开发板管理器没有 esp32，首选项的附加开发板管理器网址添加：

   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`

4. 打开 `SkiMaster/SkiMaster.ino`，选择实际 S3 板型；通用板可从 **ESP32S3 Dev Module** 开始。选择串口，上传。
5. 打开 `SkiNode/SkiNode.ino`，选择实际 C3 板型；通用板可从 **ESP32C3 Dev Module** 开始。
6. 分别将分控文件顶部 `NODE_ID` 改为 1、2、3、4，每改一次上传到对应板，并给板子贴上标签。
7. 原生 USB 连接的板子通常需要 **USB CDC On Boot → Enabled**；使用 USB 转串口的开发板按其说明设置。上传失败可尝试按住 BOOT、短按 RESET，再开始上传。
8. 打开串口监视器，波特率 **115200**。

代码只依赖 ESP32 开发板包自带的 Wire、WiFi、ESP-NOW，无需另装 MPU6050 库。不要移动 .ino 而漏掉同目录的 MotionCommon.h。

## 8. 安装方向与校准

本版使用互补滤波估计传感器坐标系下的 roll/pitch，输出减去静止校准时的初始角度。它不是完整的人体关节姿态重建。

为了避免欧拉角奇异点，安装时让 IMU 的 **X 轴大致水平**，不要把 X 轴朝向竖直方向。一个容易统一的起点是：传感器板面贴近身体、X 轴朝身体左侧、Y 轴向上、Z 轴朝外；以传感器芯片轴向标记为准。左右肢体尽量使用相同坐标约定，固定牢固，不要让衣物单独带动模块晃动。实际 roll/pitch 对应哪种人体动作，需要通过缓慢前倾、侧倾现场确认。

上电即进行约 3 秒校准，请保持静止。主控串口发送 `c` 会请求所有分控重新校准，自己也重新校准。广播不保证送达，必须确认各分控串口出现 `CAL OK`；如有节点未收到，单独通过该分控串口发送 `c`。这里没有实现无线校准完成确认。

校准时检测到明显运动会失败；采样失败、长时间暂停或接近 pitch ±90° 时也会标记为无效。修复原因后重新校准；初始化失败则检查接线后复位。该简化滤波适合有限倾角的原型演示，大幅旋转、翻滚与准确关节分析需改用四元数姿态融合及完整安装标定。

## 9. 操作顺序

1. 先不接马达，检查供电、地线、I²C 接线。
2. 逐个烧录节点并确认 `CAL OK`。
3. 主控串口应显示 `N1[OK...]` 至 `N4[OK...]`；缓慢移动对应模块，确认对应编号的角度变化。
4. 断电后接入 DRV8833 和马达，再上电。主控发送 `t`，测试一次约 150ms 振动。
5. 按统一的中立姿势安装，发送 `c`，保持静止，确认五个传感器校准完成。
6. 发送 `a`，在胸口和四个分控均有效时启用自动提醒。
7. 发送 `s`，立即关闭自动提醒和马达。

| 主控串口字符 | 功能 |
|---|---|
| c | 停止提醒，广播校准请求，校准胸口；完成后仍保持停止 |
| a | 所有传感器有效时启用自动提醒 |
| s | 停止自动提醒及马达 |
| t | 独立马达测试，约 150ms；允许在未启用提醒时使用 |

发送单个小写字母即可，换行会被忽略。自动提醒不会在开机后自行启用。任何分控超过 350ms 无有效更新、或任一传感器报无效，会关闭自动提醒；恢复后需要重新发送 `a`。

## 10. 修改动作提醒

在主控文件顶部修改这些常量：

| 常量 | 默认值 | 含义 |
|---|---|---|
| ROLL_LIMIT | 20° | 胸口 roll 偏离校准姿势的阈值 |
| PITCH_LIMIT | 25° | 胸口 pitch 偏离校准姿势的阈值 |
| HYSTERESIS | 4° | 回到阈值以下 4°才解除超限状态 |
| HOLD_MS | 800ms | 超限状态持续多久后提醒 |
| GAP_MS | 2500ms | 两次提醒的最小间隔 |
| PULSE_MS | 150ms | 单次振动时长 |
| MOTOR_DUTY | 160/255 | 振动 PWM 占空比 |
| ENABLE_LIMB_ALERTS | false | 改成 true 后启用四肢阈值提醒 |
| LIMB_ROLL_LIMIT | 45,45,30,30° | 按左臂、右臂、左腿、右腿顺序配置 |
| LIMB_PITCH_LIMIT | 45,45,30,30° | 同上 |

启用四肢提醒后，胸口或任一肢体超限都可触发同一种振动。单个胸口马达当前不会区分哪一个肢体出现偏差；通过串口角度查看来源。所有数值都只是调试初值，不代表正确的滑雪动作范围。没有明确动作标准前，保持四肢提醒关闭。

马达电源仍须稳压到额定电压，不能用降低 PWM 占空比替代正确供电。

## 11. 通信和数据说明

- 固定 Wi-Fi 信道 6，不连接路由器；五块板的信道、GROUP_ID、VERSION 必须一致。
- 为免手填 MAC，本版使用 ESP-NOW 广播：分控发送数据，主控按节点 ID 接收；主控广播校准命令。
- 每个 IMU 约 100Hz 采样，分控约 23～24Hz 发送，主控约 4Hz 打印；不是硬实时保证。
- 数据包为 52 字节，含组标识、版本、类型、节点 ID、有效标记、随机启动 ID、序号、本机采样时间和 8 个 float。
- roll/pitch 单位为度；ax/ay/az 为 g；gx/gy/gz 为度/秒。加速度包含重力；陀螺仪扣除了静止偏置。
- sampleMs 是节点自己的开机时间，**各节点时钟没有同步，不能用于精确跨节点同时刻比较**。主控用本地接收时刻检测断线，只判断各节点独立阈值，没有计算左右同步、相对关节角或轨迹。
- `age` 为接收数据距现在的毫秒数；`miss` 是依据序号估计的漏帧数量，包含队列丢弃等影响，并非精确射频丢包率。
- `enqueueErrors` 只统计发送入队失败，不代表无线送达率。
- 同一个 ID 同时出现两个发射器时，主控暂时保留活跃节点；仍需保证 ID 唯一。
- 广播不加密，GROUP_ID 只是分组过滤，不是身份认证。同一区域有多套装置时先修改 GROUP_ID；正式产品应增加固定配对、身份验证和可靠控制命令确认。

## 12. 已知边界与排查

一个肢体只装一颗 IMU，无法单独获得准确的膝/肘关节角。两款 IMU 都没有磁力计，本版不输出绝对航向、位置、脚底压力或身体重心。动态加速度会影响倾角，马达振动也会造成扰动，应先室内联调再验证实际运动数据。

| 现象 | 排查 |
|---|---|
| MPU 初始化失败 | 检查 3.3V、共地、SDA/SCL、AD0、6500 的 CS、芯片实际型号 |
| CAL failed | 保持静止；确认传感器 X 轴没有接近竖直；发送 c 重试 |
| 节点 OFF | 核实 ID、信道、组标识、供电及分控 CAL OK；检查衣物/人体遮挡 |
| 马达不转 | 检查 nSLEEP、VM、公共地、两个 AOUT、马达类型及启动电流 |
| 马达一转主控重启 | 检查稳压器峰值能力、去耦、电池和走线 |
| 提示缺少 esp_now_recv_info_t 或 ledcAttach | 使用 Arduino-ESP32 3.0.7，不是 2.x |
